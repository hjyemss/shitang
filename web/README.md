# 智慧食堂综合调度中心 · 总控大屏（静态演示版）

> 人大附中「智慧食堂综合管理与健康分析系统」第一阶段：**一个不依赖环境的总控网页**。
> 纯 HTML + CSS + JS，双击就能打开，答辩现场断网也能演示。

---

## 一、怎么打开

| 方式 | 操作 | 说明 |
| --- | --- | --- |
| **最简单** | 双击 `dist/智慧食堂总控大屏.html` | 单文件，样式 / 脚本 / 数据全在里面，可直接发给别人 |
| 开发调试 | 双击 `web/index.html` | 多文件版本，改 `data/*.json` 立即生效（点右上角「刷新」） |
| 本地服务 | `cd web && python3 -m http.server 8600` → 打开 `http://localhost:8600` | 想模拟「真实读取 JSON」时用 |

> 不需要安装 Python 包、不需要 Node、不需要后端。只要能开浏览器。

改完数据后重新打包单文件：

```bash
python3 tools/build_single_file.py     # → dist/智慧食堂总控大屏.html
```

## 二、页面结构

| 页面 | 内容 |
| --- | --- |
| **系统总览** | 四个核心 KPI、今日分时人流曲线、模块接入状态、楼层承载、实时告警时间线、系统资源 |
| **排队拥堵监控** | 拥挤告警条、窗口排队柱状图（含 20 人阈值线）、窗口明细表、近 3 小时趋势、八路摄像头阵列 |
| **楼层分流建议** | AI 分流建议卡、三层座位使用率、就餐人数占比环形图、楼层状态表、三层人流堆叠图 |
| **营养健康分析** | 学生选择、六维营养雷达图、热量 / 蛋白质趋势、餐次构成、营养师建议、点餐流水、家长周报推送 |
| **扩展与接入** | 模块槽位、通用模块示例、三种接入方式说明、给合作方的扩展规则 |
| **新分项目 A / B** | 预留的空槽位页（零代码生成，用来演示「以后可以加新分项目」） |

右上角两个按钮：**主题**（深色 / 浅色切换，会记住选择）、**刷新**（重新读取 `data/*.json`）。

## 四、给合作方的三个入口

1. **只交数据（最常用）**：把自己的算法结果写成 `web/data/<模块>.json`，字段照 `docs/INTERFACE.md`。
   页面刷新即生效，**不用碰任何前端代码**。
2. **实时推送**：`Platform.registerDataSource('queue', fn)`，`fn` 每次返回同构对象，平台会用它覆盖 JSON。
   适合已有后端、WebSocket、行空板串口转发的场景。
3. **新分项目**：在 `web/data/extensions.json` 里填一个槽位（零代码），或写 `assets/js/modules/<名字>.js`
   调 `Platform.registerPage({id, label, icon, render})` 注册新导航页。**各写各的文件，互不冲突**。

三个分模块（排队 / 楼层 / 营养）目前在数据里都标记为「待接入」或「模拟数据」，
拿到真实数据后只需替换对应 JSON。

## 五、数据说明（重要）

- 页面里所有数字都是**演示数据**，来自菜品 / 窗口 / 餐卡流水的仿真种子（2026-11-17）。
- `data/nutrition.json` 里的 12 个学生、点餐记录是模拟的，**不是真实学生信息**。
- 点「生成并推送家长微信」只会在页面上给出成功提示，**不会真的发送**，也不上传任何数据。
- 需要换日期 / 换人：直接改 `nutrition.json` 的 `students`，或跑 `tools/export_web_data.py` 重新生成。

## 六、已知边界

| 项 | 现状 | 后续 |
| --- | --- | --- |
| 数据实时性 | 静态 JSON，手动刷新 | 接 WebSocket / 轮询即可，接口已留 |
| 摄像头画面 | 只有设备卡片，没有视频流 | 第二阶段接 YOLO 检测流（`<video>` / MJPEG） |
| 微信推送 | 前端模拟 | 后端企业微信机器人 / 服务号接口 |
| 权限 / 登录 | 无 | 校内网部署时再加 |
| 移动端 | 侧边栏会折叠成横排，可用但未精修 | 演示用大屏为主 |
